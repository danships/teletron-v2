# S1-PR4 — Persist nodes and token grants

- Parent spec: [Spec 001](../001-hub-and-first-display.md)
- Slice PR: 4
- Ticket type: Story

## Overview

Add the hub persistence boundary for logical nodes and their hashed credentials.
This PR creates only the `nodes` and `node_tokens` tables and repository
operations; it has no CLI, control socket or WebSocket behavior.

---

## Tech Stack

- `supersave` — ADR-004 data access boundary.
- `mysql2` — MySQL driver used through supersave.

Install both directly in `apps/hub` with pnpm and `--ignore-scripts`; state the
reason for each in the PR description.

---

## Data Model

### `nodes`

Stable logical node identity; new table.

| Field        | Type          | Notes                                     |
| ------------ | ------------- | ----------------------------------------- |
| `id`         | UUID string   | Primary key, generated by the application |
| `name`       | varchar(63)   | Unique, immutable, validated logical name |
| `created_at` | UTC timestamp | Required                                  |

### `node_tokens`

Hashed node credentials and exact grants; new table.

| Field        | Type                         | Notes                                |
| ------------ | ---------------------------- | ------------------------------------ |
| `id`         | UUID string                  | Primary key                          |
| `node_id`    | UUID string                  | Required foreign key and indexed     |
| `token_hash` | fixed SHA-256 representation | Required and unique; never plaintext |
| `grants`     | JSON                         | Required; strict token-grant schema  |
| `created_at` | UTC timestamp                | Required                             |
| `revoked_at` | UTC timestamp                | Nullable                             |

**Relationships**

- `node_tokens.node_id` → `nodes.id` — many tokens to one node; restrict delete
  and update.

**Migration strategy**

- Additive initial migration. Rollback drops `node_tokens` before `nodes` only in
  disposable development/test databases; production rollback keeps credential
  records and rolls application code forward.

4. [ ] Add startup configuration parsing in `apps/hub/src/config/database.ts`;
       reject absent/non-MySQL URLs without echoing credentials.
5. [ ] Add the supersave connection factory in `apps/hub/src/db/database.ts` and
       the two table definitions/migration under `apps/hub/src/db/schema/`.
6. [ ] Add `apps/hub/src/nodes/node-repository.ts` with operations to create a
       node and first token atomically, load a token by SHA-256 hash, revoke by
       token ID and issue a token only when no active token exists.

       stored grants as a closed authentication failure, never as an empty or
       permissive grant set.
8. [ ] Keep hashing/random token generation outside this repository. Accept only
       the hash and repository records so PR5 can own one-time secret handling.
9. [ ] Export the database/repository composition from the hub without adding a
       network listener, then run database tests and `pnpm check`.

## Acceptance Tests Covered

- **AT-D01:** Given an empty database, when migrations run, then the node and
  token tables, keys, indexes and restrictions match this spec.
- **AT-D02:** Given duplicate node names or token hashes, when inserted, then the
  database rejects them.
- **AT-D03:** Given malformed grants JSON read from storage, when the data
  boundary loads it, then it fails closed before authentication.
- **AT-D04:** Given a node with an active token, when another token issuance is
  attempted, then it is rejected without changing either record.

---

## Edge Cases & Error Handling

- **Concurrent issuance:** Enforce the single-active-token invariant inside one
  transaction with a locked node/token read; a loser makes no write.
- **Duplicate key races:** Map MySQL constraint failures to stable repository
  conflicts without including SQL or connection data.
- **Malformed stored JSON:** Return a typed closed failure and record only row
  IDs in safe diagnostics.
- **Database unavailable:** Fail hub composition before any listener starts.

---

## Security Considerations

- **Authentication and authorization:** Repository lookup uses only SHA-256 token
  hashes; it excludes revoked records from successful authentication.
- **Input validation:** Shared node-name and strict grant schemas protect every
  write/read boundary.
- **Sensitive data exposure:** `DATABASE_URL` and plaintext tokens never appear
  in errors, entities or test snapshots.
- **Audit logging:** Repository returns IDs and outcomes for later audit logging;
  it does not log secrets or grant payloads itself.
